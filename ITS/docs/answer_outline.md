# 答辩表述提纲

## 1. 项目名称

推荐名称：

```text
基于 FPGA + RK3568 的智能交通多目标识别与态势感知系统
```

## 2. 一句话介绍

本系统利用 FPGA 完成视频采集和低延迟图像链路，利用 RK3568 NPU 运行轻量化 YOLO 模型识别交通场景中的行人、车辆和交通灯，并结合道路语义区域规则实现交通风险提示。

## 3. 为什么这样设计

传统 CPU/GPU 方案在嵌入式场景中存在功耗高、实时性和部署灵活性不足等问题。本系统采用 FPGA + RK3568 的异构架构：

- FPGA 负责视频采集、格式整理和高速传输。
- RK3568 NPU 负责神经网络推理。
- CPU 负责可解释的交通规则判断。

这样可以在不额外训练复杂行为模型的前提下，完成可演示、可部署的智能交通感知闭环。

## 4. 功能点

基础识别：

- 行人识别。
- 小汽车、公交车、卡车、摩托车识别。
- 交通灯识别。
- 类别计数和画框显示。

交通风险规则：

- 行人进入机动车道风险。
- 车辆进入人行区域风险。
- 人车混行风险。
- 车辆密度过高风险。

可选扩展：

- 疑似闯红灯风险。
- 疑似逆行风险。
- 疑似越线风险。

## 5. 创新点说法

推荐说法：

```text
系统在交通目标检测基础上引入可配置道路语义区域，将神经网络输出的检测框转换为交通风险事件，实现了从“目标识别”到“场景态势感知”的扩展。
```

可以强调：

- 不只是单纯 YOLO 画框。
- ROI 规则可解释、可配置。
- 后续可扩展到闯红灯、逆行、越线等更复杂行为。
- FPGA 视频链路和 RK3568 NPU 推理形成端到端嵌入式系统。

## 6. 面对评委追问

问：你们是否真正识别了闯红灯？

答：

```text
当前版本不直接训练端到端闯红灯行为模型，而是采用交通灯状态、斑马线区域和行人位置关系进行规则化风险标记。我们将其定义为“疑似闯红灯风险提示”，这种方式可解释、部署成本低，也为后续接入行为识别模型预留了接口。
```

问：为什么不用专门的违法行为数据集训练？

答：

```text
违法行为识别需要固定机位、多帧时序数据和高质量行为标注，短周期内训练风险较高。本项目更关注 FPGA + RK3568 端到端智能交通感知系统的实现，因此优先采用成熟 COCO 预训练模型和规则化场景理解方法，保证系统可运行、可演示、可部署。
```

问：这个系统和普通 YOLO Demo 有什么区别？

答：

```text
普通 YOLO Demo 只输出目标框，本系统进一步结合道路区域语义，对目标进行区域归属和交通风险判断，并且系统前端接入 FPGA 视频链路，目标是嵌入式实时交通感知，而不是离线图片检测。
```
